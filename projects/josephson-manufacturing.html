Client Full-Stack Website

Josephson Manufacturing

A manufacturing website designed around a simple public experience and a focused administrative system for the content that needed regular updates.

Angular / Node.js / MongoDB / AWS

02 Overview

Project Overview

Simple for visitors and maintainers

The project was designed for a radiator manufacturing company that needed a straightforward website and control over two sections that changed more frequently.

03 Challenge

The Challenge

Avoiding an oversized CMS

Most of the site could remain static. Only the content that actually changed needed an administrative workflow.

Building only what the project needed

Instead of introducing a large content-management platform, I created a focused backend for adding, editing, and deleting records in the two dynamic areas.

A login flow protected the management tools. Once authenticated, the interface exposed an additional administrative menu for the authorized content workflows.

Project constraints

  • A simple public-facing website
  • Only two sections required dynamic content
  • Authenticated administrative actions
  • Separate frontend and backend deployments
  • A maintainable stack without unnecessary complexity
04 Build

Key Implementation

A focused full-stack architecture

Angular handled the interface while Node, Express, and MongoDB supported authentication and the dynamic content workflows.

01

Angular frontend

The public website and authenticated management views shared one responsive application structure.

02

Node + Express API

Backend routes handled login and the create, edit, and delete actions required by the dynamic sections.

03

MongoDB storage

The database stored the records that company staff needed to maintain without editing source files.

04

AWS deployment

The original architecture separated the frontend on Amazon S3 from the backend hosted through Elastic Beanstalk.

05 Details

Supporting Details

Practical features around the core build

The application included the supporting pieces needed to make the focused administration system useful.

  • Login-protected content management
  • Administrative navigation shown after authentication
  • Create, edit, and delete operations for dynamic records
  • Nodemailer integration for email functionality
  • Bootstrap used for interface structure and responsiveness
  • Git and GitHub used to track the project
06 Reflection

Project Reflection

An early full-stack client build

The project remains valuable because it shows how I approached a real client need with a deliberately limited administrative scope.

What it demonstrates

Requirements-based architecture, authenticated administration, database-backed content, and separate cloud deployment of a frontend and backend.

What I would modernize

I would revisit accessibility, automated testing, dependency versions, deployment automation, and the visual system using the standards applied in my current projects.
